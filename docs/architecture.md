# Architecture notes

How the pieces fit together, and the rules to keep in mind when changing them.

- **Product:** Silica. The index is the Silica Compute Index (id `SCI`), the market is `SCI-1H` (futures on NEAR, hourly markets, cash-settled in tUSDC).
- **Contract:** `contracts/near/silica` (Rust, crate `silica`), plus `contracts/near/mock-ft` (test collateral token). Live at `gasx.testnet`; collateral `tusdc.gasx.testnet`; oracle `oracle.gasx.testnet`. **Account ids keep the project's original name**: they are on-chain and cannot be renamed. One current market; `roll_market` is callable by the owner or publisher. ABI in `docs/near-abi.md`.
- **Packages** (each has its own `package.json` and lockfile; there is no root workspace):
  - `blockchain/near` is `@silica/near-adapter`: reads the contract over JSON-RPC, prepares (never signs) wallet transactions, and hosts the cron `runTick` (publish, settle, roll, optional demo liquidity, match). Pure helpers live in `pricing.ts`.
  - `server` is `@silica/server` (Fastify): REST API, compute index, risk policy, chat, optional Postgres. It depends on the adapter through `"file:../blockchain/near"`, so the adapter must be built (`dist/`) first.
  - `frontend` is `@silica/frontend` (Vite + React).
- **Deployment:** Vercel serves `frontend/dist` and one serverless function, the esbuild bundle `api/index.js`, which is **committed**. After any server or adapter change run `npm --prefix server run build:vercel`, or the deploy ships old code. `vercel.json` needs `"framework": null`, and its build command installs and builds `blockchain/near` and `frontend` only (lockfiles must stay in sync). There is no Docker stack and no separate AI service.
- **Cron:** Supabase `pg_cron` + `pg_net` call `/api/v1/cron/tick` every minute and `/api/v1/cron/compute-snapshot` every 15 minutes (`supabase/migrations/0002_cron.sql`, `0004_compute_cron.sql`), authenticated by the shared `CRON_SECRET`. The frontend also pokes `/api/v1/market/poke` (rate limited). One account, the publisher, signs everything the tick does.
- **Database:** optional Postgres (Supabase), schema in `supabase/migrations`. The server runs without it (`SILICA_API_DATABASE_URL` unset).
- **Environment variables:** named `SILICA_*`. The original `GASX_*` names are still read as a fallback (SILICA wins when both are set), because the live Vercel environment still uses them, including the publisher private key. Each package reads env through one helper, `readEnv(name)` in `blockchain/near/src/env.ts` and `server/src/env.ts`; never read `process.env.SILICA_*` directly. `CRON_SECRET` and `VITE_*` keep their names. `scripts/setup-vercel-secrets.ps1` sets `SILICA_NEAR_PUBLISHER_PRIVATE_KEY`.
- **Demo liquidity:** `runTick` can quote a bid and ask from the publisher account (`SILICA_DEMO_LIQUIDITY=true`); see `docs/market.md`.
- **Compute Index:** `server/src/compute/`, methodology in `docs/compute-index.md`. Matched quotes: every quote is compared only with its own base in `base.ts`. Adding a venue or product needs a new methodology version and `server/scripts/snapshotCompute.ts --write-base`.
- **Frontend:** entry `frontend/src/main.tsx` renders `shell/App.tsx`; pages in `pages/`, wallet code in `wallet/` (needs `polyfills.ts`), styling in `ui/silica.css`, index experience in `compute/`.
- **Images:** `frontend/public/img/compute/`, attribution in `frontend/src/lib/imageCredits.json`. Every image needs an entry; the credits section renders from it. CC BY/BY-SA require attribution.
- **Tests:** `scripts/test-all.sh [all|typescript|frontend|contracts]` runs everything; CI (`.github/workflows/tests.yml`) runs the same suites on Linux.
- **Windows:** long checkout paths break some Node tools; map a short drive with `subst` (for example `subst G: <parent folder>`) and work from there. `server/node_modules/@silica/near-adapter` is a junction to `blockchain/near`, so keep the repo folder itself unchanged. Rust on Windows builds with the GNU toolchain plus `AWS_LC_SYS_PREBUILT_NASM=1`.
